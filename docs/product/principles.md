# Product principles

1. **Publish ideas, not infrastructure.** The publishing system should stay smaller than the writing problem.
2. **Markdown is the source of truth.** Avoid CMS or workflow machinery unless file-based publishing becomes a real constraint.
3. **Prefer clear arguments over ornamental content.** Diagrams and UI should clarify the writing, not compete with it.
4. **Keep the path from idea to post short.** The Obsidian ideas pipeline should feed the repository without bureaucratic ceremony.
5. **Technical credibility matters.** Claims should be grounded in experience, trade-offs, and inspectable examples.
6. **Static by default.** Favor a build-time site when interactivity or server state does not create reader value.
7. **Do not create a draft illusion.** If every Markdown post ships, make that behavior explicit and easy to understand.
8. **Optimize for reading.** Typography, navigation, code, diagrams, and mobile behavior serve comprehension.
9. **Avoid platform work that does not improve writing or reading.**
